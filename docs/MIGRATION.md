## Подключение Supabase

Создать отдельный проект HramGo в существующей организации. Посторонний проект TopRepet не используется. Сохранить пароль базы у себя. Форма проекта открыта в браузере; это единственный текущий пользовательский шаг, без которого нельзя выполнить перенос.

Создать приватный `.env.local` по `.env.example`: URL, publishable key, secret key для мигратора и SSL connection string базы. Не передавать secret key в `NEXT_PUBLIC_*` или переменные сборки Pages. Для запуска скриптов использовать `node --env-file=.env.local`.

Последовательность (после создания проекта):

```powershell
node --env-file=.env.local scripts/apply-migrations.mjs
node --env-file=.env.local scripts/migrate-legacy.mjs tmp/backups/legacy-data.json
node --env-file=.env.local scripts/migrate-legacy.mjs tmp/backups/legacy-data.json --apply
node --env-file=.env.local scripts/refresh-official.mjs --legacy-export=tmp/backups/legacy-data.json --apply
node --env-file=.env.local scripts/apply-reviewed-assets.mjs --apply
node --env-file=.env.local scripts/optimize-photos.mjs tmp/backups/legacy-data.json --upload
node --env-file=.env.local scripts/sync-catalog.mjs
```

Мигратор допускает только пустую целевую базу или возобновление своего журнала с тем же checksum. Храмы скрыты до проверки основных связей и количества персональных записей. До окончательного переключения нужен повторный экспорт старой базы, если после резервирования появились новые отзывы/пользователи/платежи.

В Supabase установить Auth Site URL/redirects из `supabase/config.toml`, подтверждение почты и двойное подтверждение смены адреса, минимальную длину пароля 10. Настроить собственный SMTP для реальной доставки регистрационных писем и восстановления старых аккаунтов; проверить отправку и ограничения. Локальный PGlite-тест проверяет настоящий PostgreSQL RLS, grants, триггеры и RPC, однако заменяет PostGIS заглушками. Реальные геозапросы, Auth, Storage и Edge Functions требуют проверки именно в новом Supabase.

## Платежи

Развернуть `create-payment` и `payment-webhook` через Supabase CLI. JWT gate выключен для новых ключей и webhook, однако создание платежа вручную проверяет bearer token и подтверждённую почту через Auth. Ключ YooKassa хранить только в Edge Function secrets. Настроить webhook URL в кабинете провайдера. Для антиспама требуется вход; гостевой платёж вернётся только после серверной CAPTCHA/защиты.

Перед включением `NEXT_PUBLIC_PAYMENTS_ENABLED=true` проверить тестовый режим: повтор одной idempotency key, ошибку провайдера, неверную сумму, неподтверждённый webhook, повтор/перестановку уведомлений, полный возврат и корректность чека. Реальная оплата не выполнялась. Возврат по кнопке провайдера или query-параметр не считается доказательством успешной оплаты. Юридические документы сохранены, но их соответствие новой обработке данных требует отдельной проверки владельцем перед запуском.

## GitHub Pages и домен
